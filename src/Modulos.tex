\subsection{Definición del Módulo: Portal Web y Control de Acceso (M1)}
\label{subsec:modulo_m1}

\begin{definicionmodulo}

\item[Propósito] El módulo Portal Web y Control de Acceso constituye el punto de interacción entre los usuarios y el Sistema Coordinador. Su propósito es proporcionar una interfaz protegida para definir solicitudes de procesamiento documental, consultar las tareas creadas y revisar su estado, avance y resultados. Además, controla el acceso a las funciones internas y mantiene la sesión del usuario durante su interacción con el sistema.

\item[Alcance] El módulo comprende el ingreso al sistema, la navegación por el portal, la configuración de nuevas solicitudes, la consulta de tareas y la visualización de sus detalles. También presenta el estado general de los servicios requeridos y comunica al usuario los errores de validación o ejecución. No consulta directamente los registros documentales, no distribuye trabajos entre servidores y no ejecuta inferencia.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Preparación de Lotes Documentales, encargado de validar la selección y construir el lote solicitado.
    \item Módulo Gestión y Orquestación Distribuida de Tareas, utilizado para crear y consultar las tareas.
    \item Servicios del back end del Sistema Coordinador, desde los cuales se recuperan estados, antecedentes y resultados.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item El usuario dispone de credenciales válidas y de permisos suficientes para las funciones solicitadas.
    \item El navegador puede establecer una conexión segura con el Sistema Coordinador.
    \item Los servicios internos entregan respuestas estructuradas que pueden ser presentadas por el portal.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item La vista de ingreso será la única vista accesible sin una sesión válida.
    \item Todo intento de acceder directamente a una ruta protegida deberá requerir autenticación.
    \item Las acciones de creación deberán bloquear envíos repetidos mientras se registra una tarea.
    \item El portal no deberá exponer credenciales, rutas internas ni información sensible de los servicios.
    \item Los mensajes mostrados al usuario deberán ser comprensibles y conservar la información necesaria para el diagnóstico.
\end{elementosmodulo}

\item[Estructura general] El módulo recibe las acciones del usuario, valida los datos ingresados, solicita las operaciones correspondientes al back end y presenta las respuestas entregadas por los demás módulos del Sistema Coordinador.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Credenciales y acciones de control de sesión.
    \item Fuente documental y criterios de selección definidos por el usuario.
    \item Parámetros del procesamiento solicitado.
    \item Acciones de consulta, cancelación o reprocesamiento de tareas.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación de formularios y parámetros ingresados.
    \item Solicitud de autenticación y mantenimiento de la sesión.
    \item Protección de rutas y funciones internas.
    \item Envío de solicitudes al Sistema Coordinador.
    \item Actualización de las vistas según el estado de cada operación.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Sesión autenticada o mensaje de rechazo.
    \item Solicitud validada de creación de una tarea.
    \item Lista y detalle de las tareas disponibles.
    \item Estado, progreso, resultados y errores de cada procesamiento.
    \item Información general sobre la disponibilidad de los servicios.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Servicio de Conexión con MySQL (M2)}
\label{subsec:modulo_m2}

\begin{definicionmodulo}

\item[Propósito] El módulo Servicio de Conexión con MySQL tiene como propósito centralizar y controlar el acceso del Sistema Coordinador a las bases de datos institucionales. Proporciona las operaciones necesarias para consultar los documentos de origen, verificar sus identificadores y almacenar los resultados autorizados sin exponer los detalles de conexión al resto de los módulos.

\item[Alcance] El módulo administra la apertura, utilización y cierre de conexiones; ejecuta consultas parametrizadas; controla transacciones; y transforma los resultados de MySQL en estructuras utilizadas por la aplicación. Atiende tanto las lecturas requeridas para preparar los lotes como las escrituras efectuadas al persistir resultados. No decide qué documentos deben procesarse ni modifica por sí mismo la estructura o el contenido original.

\item[Dependencias]
\begin{elementosmodulo}
    \item Servidor MySQL institucional y su controlador de conexión.
    \item Configuración protegida con las direcciones, credenciales y tiempos de espera autorizados.
    \item Módulo Preparación de Lotes Documentales, que solicita la lectura de documentos y metadatos.
    \item Módulo Persistencia y Trazabilidad de Resultados, que solicita escrituras controladas.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item El servidor MySQL es accesible desde el Sistema Coordinador.
    \item Las credenciales configuradas poseen los permisos mínimos necesarios para cada operación.
    \item Los registros documentales cuentan con identificadores que permiten relacionar origen y resultado.
    \item Las estructuras consultadas mantienen los campos requeridos por la configuración activa.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item Las credenciales no deberán registrarse en logs ni incluirse en las respuestas del sistema.
    \item Toda consulta que incorpore valores externos deberá utilizar parámetros.
    \item Las escrituras relacionadas deberán ejecutarse dentro de una transacción.
    \item Los tiempos de conexión y ejecución deberán estar limitados para evitar bloqueos indefinidos.
    \item Las operaciones no deberán eliminar ni sobrescribir el documento original.
\end{elementosmodulo}

\item[Estructura general] El módulo recibe una operación de lectura o escritura, selecciona la conexión autorizada, ejecuta la sentencia parametrizada y devuelve una respuesta independiente del controlador utilizado.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Identificación de la conexión y de la base de datos autorizada.
    \item Consulta parametrizada y valores asociados.
    \item Datos de transcripción, estado y trazabilidad que deben persistirse.
    \item Parámetros de transacción y tiempo máximo de ejecución.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación de la operación solicitada.
    \item Apertura o reutilización controlada de la conexión.
    \item Ejecución de consultas o transacciones parametrizadas.
    \item Conversión de tipos y resultados al modelo interno.
    \item Confirmación o reversión de las escrituras.
    \item Cierre y liberación de los recursos utilizados.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Registros y documentos recuperados desde MySQL.
    \item Confirmación de las operaciones de persistencia.
    \item Identificadores necesarios para mantener la relación con el origen.
    \item Errores de conexión, permisos, consulta o transacción normalizados.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Preparación de Lotes Documentales (M3)}
\label{subsec:modulo_m3}

\begin{definicionmodulo}

\item[Propósito] El módulo Preparación de Lotes Documentales tiene como propósito transformar una solicitud de procesamiento en un conjunto definido, validado y reproducible de documentos. De este modo, cada tarea conoce con precisión qué registros debe procesar y cómo recuperar su contenido.

\item[Alcance] El módulo interpreta la fuente, los criterios y el rango indicados por el usuario; consulta los registros disponibles; valida la existencia y compatibilidad de cada documento; y construye las referencias que componen el lote. También determina la cantidad efectiva de elementos y asocia la configuración de procesamiento que será entregada al orquestador. No ejecuta inferencia ni almacena los resultados generados.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Portal Web y Control de Acceso, desde el cual se recibe la solicitud del usuario.
    \item Módulo Servicio de Conexión con MySQL, utilizado para consultar y validar los registros documentales.
    \item Módulo Gestión y Orquestación Distribuida de Tareas, encargado de registrar y ejecutar el lote.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item Cada registro seleccionado posee un identificador estable.
    \item El documento o una referencia suficiente para recuperarlo se encuentra disponible en la fuente.
    \item El usuario posee permisos para consultar los registros incluidos en la solicitud.
    \item Los formatos admitidos pueden identificarse antes de iniciar el procesamiento.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item No se podrá crear un lote sin una fuente documental y criterios de selección válidos.
    \item Un mismo registro no deberá incorporarse más de una vez al mismo lote.
    \item Las consultas deberán limitarse a los campos y registros necesarios para construir el lote.
    \item Los documentos incompatibles deberán rechazarse o marcarse antes de ser enviados a un VLM Server.
    \item El orden y los límites de la selección deberán mantenerse para permitir su reproducción.
\end{elementosmodulo}

\item[Estructura general] El módulo valida la solicitud, consulta los registros que cumplen sus criterios y genera un manifiesto con las referencias individuales y la configuración necesaria para crear la tarea.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Fuente de datos y conjunto documental seleccionado.
    \item Identificador inicial, identificador final u otros criterios de selección.
    \item Cantidad máxima de registros.
    \item Modelo, perfil y parámetros de procesamiento solicitados.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación de la fuente y de los criterios recibidos.
    \item Consulta de los registros candidatos.
    \item Verificación de identificadores, disponibilidad y formato documental.
    \item Eliminación de duplicados dentro de la selección.
    \item Construcción de las referencias individuales.
    \item Generación del manifiesto y resumen del lote.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Lote documental validado.
    \item Lista ordenada de registros y referencias documentales.
    \item Cantidad efectiva de elementos que serán procesados.
    \item Perfil y parámetros asociados al lote.
    \item Detalle de los registros rechazados durante la validación.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Gestión y Orquestación Distribuida de Tareas (M4)}
\label{subsec:modulo_m4}

\begin{definicionmodulo}

\item[Propósito] El módulo Gestión y Orquestación Distribuida de Tareas tiene como propósito controlar el ciclo de vida de los procesamientos documentales y distribuir su ejecución entre uno o más VLM Server. Mantiene la relación entre cada tarea, sus documentos, el servidor asignado y el estado alcanzado, permitiendo procesar grandes volúmenes de manera paralela, recuperable y trazable.

\item[Alcance] El módulo crea las tareas, divide los lotes en elementos individuales, registra las instancias VLM disponibles, selecciona servidores compatibles, despacha documentos, actualiza el progreso y controla errores, reintentos, cancelaciones y reprocesamientos. También recupera las tareas que hayan quedado incompletas después de una interrupción y evita que un mismo elemento sea ejecutado simultáneamente por más de un servidor.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Preparación de Lotes Documentales, que entrega el lote validado.
    \item Módulo API de Integración con VLM Server, utilizado para consultar servidores y enviar documentos.
    \item Módulo Persistencia y Trazabilidad de Resultados, utilizado para conservar estados, asignaciones y resultados.
    \item Configuración de las instancias VLM Server y sus capacidades.
    \item Almacenamiento persistente del Sistema Coordinador para recuperar la ejecución.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item Cada tarea y cada elemento documental poseen identificadores únicos.
    \item Cada VLM Server informa su disponibilidad, modelo activo y resultado de las solicitudes.
    \item Las instancias pueden disponer de modelos y capacidades de procesamiento diferentes.
    \item El estado persistido permite reconstruir las tareas después de una interrupción.
    \item Una tarea puede continuar aunque falle uno de sus documentos o servidores.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item La asignación deberá respetar la compatibilidad y concurrencia admitidas por cada VLM Server.
    \item Un mismo elemento no deberá ejecutarse simultáneamente en más de una instancia.
    \item La caída de un servidor no deberá eliminar los resultados obtenidos previamente.
    \item Los reintentos y reasignaciones deberán poseer límites configurables.
    \item Toda transición de estado y cambio de servidor deberá quedar registrado.
    \item La cancelación de una tarea no deberá eliminar los resultados ya confirmados.
\end{elementosmodulo}

\item[Estructura general] El módulo registra el lote como una tarea, consulta el estado de los VLM Server y asigna cada elemento pendiente a una instancia compatible. Durante la ejecución supervisa las solicitudes, persiste el progreso y recupera o reasigna los elementos que no hayan finalizado correctamente.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Lote documental y configuración de procesamiento.
    \item Registro de VLM Server disponibles.
    \item Estado, modelo, capacidad y carga de cada servidor.
    \item Respuestas, tiempos y errores de procesamiento.
    \item Solicitudes de cancelación, reintento o reprocesamiento.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Creación de la tarea y de sus elementos individuales.
    \item Selección y reserva de documentos pendientes.
    \item Selección del VLM Server compatible disponible.
    \item Envío de documentos y seguimiento de las solicitudes.
    \item Registro de asignaciones, intentos y transiciones de estado.
    \item Aplicación de reintentos, reasignaciones y cancelaciones.
    \item Recuperación de tareas interrumpidas.
    \item Cálculo del progreso y del estado final.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Identificador y estado general de la tarea.
    \item Estado individual y servidor asignado a cada documento.
    \item Cantidad de elementos pendientes, en ejecución, completados y fallidos.
    \item Solicitudes de persistencia de resultados y errores.
    \item Historial de intentos, reasignaciones y reprocesamientos.
    \item Información de progreso disponible para el portal.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: API de Integración con VLM Server (M5)}
\label{subsec:modulo_m5}

\begin{definicionmodulo}

\item[Propósito] El módulo API de Integración con VLM Server proporciona el contrato de comunicación entre el Sistema Coordinador y cada servicio especializado de procesamiento documental. Su propósito es exponer operaciones controladas para consultar el estado del servidor y sus modelos, ejecutar la transcripción de documentos y obtener antecedentes de diagnóstico sin revelar la implementación interna del servicio.

\item[Alcance] El módulo atiende solicitudes HTTP de estado, modelos, administración, logs y procesamiento. Recibe imágenes o archivos PDF, valida sus parámetros, conserva temporalmente la carga cuando es necesario y convierte cada solicitud en un comando para el servicio VLM local. Finalmente, devuelve una respuesta uniforme con el resultado, los metadatos de ejecución o el error producido.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Gestión y Orquestación Distribuida de Tareas, que genera las solicitudes remotas.
    \item Módulo Administración del Servicio VLM, encargado de ejecutar los comandos recibidos.
    \item Canal local de comunicación entre la API y el servicio VLM.
    \item Directorios controlados para cargas temporales, resultados y logs.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item El servicio VLM y su canal interno se encuentran disponibles en el servidor.
    \item El Sistema Coordinador conoce los endpoints y contratos de respuesta.
    \item Los documentos enviados cumplen los formatos y tamaños admitidos.
    \item La instancia cuenta con espacio temporal suficiente para recibir el documento.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item La API deberá ser el único punto de acceso remoto a las funciones del VLM Server.
    \item Las cargas deberán almacenarse únicamente en rutas temporales controladas.
    \item Las solicitudes deberán contemplar tiempos máximos de espera y cancelación.
    \item Los errores internos deberán traducirse a respuestas interpretables por el Sistema Coordinador.
    \item Los archivos temporales deberán eliminarse al finalizar o abortar la operación.
\end{elementosmodulo}

\item[Estructura general] El módulo recibe una solicitud HTTP, valida el contenido, la transforma en un comando interno y devuelve la respuesta estructurada producida por el VLM Server.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Solicitudes HTTP de estado, modelos, administración y logs.
    \item Imagen o archivo PDF enviado para su procesamiento.
    \item Modelo, perfil y parámetros solicitados.
    \item Identificadores de correlación y control de la operación.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación de autenticidad, formato y parámetros de la solicitud.
    \item Almacenamiento temporal y seguro del documento recibido.
    \item Construcción y envío del comando al servicio VLM local.
    \item Espera controlada de la respuesta.
    \item Conversión del resultado interno al contrato HTTP.
    \item Eliminación de la carga temporal.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Estado operativo del VLM Server.
    \item Lista de modelos disponibles y modelo activo.
    \item Confirmación de las operaciones administrativas.
    \item Resultado documental estructurado.
    \item Código de estado y detalle normalizado de los errores.
\end{elementosmodulo}

\end{definicionmodulo}

\Needspace{8\baselineskip}
\subsection{Definición del Módulo: Administración del Servicio VLM (M6)}
\label{subsec:modulo_m6}

\begin{definicionmodulo}

\item[Propósito] El módulo Administración del Servicio VLM constituye el núcleo operativo de cada VLM Server. Su propósito es mantener el estado global de la instancia, controlar el ciclo de vida de los modelos y motores, serializar las operaciones incompatibles y coordinar los componentes responsables de la inferencia, el diagnóstico y la limpieza de recursos.

\item[Alcance] El módulo recibe y distribuye comandos internos; descubre configuraciones; inicia, supervisa y detiene los procesos de inferencia; activa o cambia modelos; informa el estado del servicio; y recarga la configuración cuando corresponde. Mantiene la información del motor y modelo activos, su estado operativo, los últimos cambios y los errores recientes.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo API de Integración con VLM Server y herramientas locales de administración.
    \item Registro de modelos y archivos de configuración del servicio.
    \item Motores y procesos externos utilizados para la inferencia.
    \item Sistema de archivos para configuraciones, sockets, logs, cargas y resultados.
    \item Módulo Procesamiento e Inferencia Documental.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item Cada modelo posee un identificador único y una configuración válida.
    \item Los ejecutables, modelos y recursos declarados se encuentran disponibles.
    \item Los puertos y canales locales requeridos pueden ser reservados por el servicio.
    \item El hardware dispone de memoria y capacidad suficientes para el motor seleccionado.
    \item Los procesos de inferencia proporcionan un mecanismo para comprobar su disponibilidad.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item Cada instancia deberá respetar el número de sesiones y operaciones simultáneas permitido por su configuración.
    \item Los cambios de motor o modelo deberán ejecutarse bajo exclusión mutua.
    \item La comunicación administrativa interna no deberá exponerse directamente a la red.
    \item Los procesos externos deberán detenerse de manera controlada antes de liberar sus recursos.
    \item Una configuración inválida no deberá reemplazar el último estado operativo conocido.
\end{elementosmodulo}

\item[Estructura general] El módulo recibe comandos internos, valida el estado actual, controla el motor solicitado y coordina la ejecución con el módulo de procesamiento, actualizando en cada etapa el estado compartido del VLM Server.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Comandos de estado, inicio, detención, cambio de modelo y recarga.
    \item Solicitudes de procesamiento documental.
    \item Solicitudes de consulta de logs y diagnóstico.
    \item Configuración de modelos, motores y límites de recursos.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación del comando y del estado actual.
    \item Descubrimiento y validación de la configuración solicitada.
    \item Inicio, comprobación, supervisión o detención del motor de inferencia.
    \item Actualización del motor, modelo y estado activos.
    \item Coordinación del procesamiento y las tareas de mantenimiento.
    \item Registro de eventos y errores operativos.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Estado actualizado de la instancia.
    \item Motor y modelo activos.
    \item Confirmación o rechazo del comando.
    \item Solicitud de inferencia coordinada.
    \item Información de diagnóstico y logs.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Procesamiento e Inferencia Documental (M7)}
\label{subsec:modulo_m7}

\begin{definicionmodulo}

\item[Propósito] El módulo Procesamiento e Inferencia Documental tiene como propósito transformar imágenes y documentos PDF en una representación textual y estructurada. Para ello prepara los archivos de entrada, procesa sus páginas mediante el motor activo y consolida un resultado que pueda ser interpretado y almacenado por el Sistema Coordinador.

\item[Alcance] El módulo admite imágenes y documentos PDF, renderiza los PDF página por página y ejecuta el flujo definido para el modelo activo. La inferencia puede utilizar un modelo multimodal o un motor OCR compatible con la configuración del servidor. El resultado incluye el contenido reconocido, la separación por páginas, el modelo y motor utilizados, los tiempos de ejecución y los errores detectados.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Administración del Servicio VLM, encargado de proporcionar un motor operativo.
    \item Herramientas de validación, conversión y renderización documental.
    \item Cliente o adaptador correspondiente al motor de inferencia activo.
    \item Configuración del modelo, prompt y parámetros de generación.
    \item Directorios temporales y de resultados.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item El documento recibido existe y puede ser leído por el servicio.
    \item El formato del archivo es compatible con el procesador documental.
    \item Existe un motor y un modelo disponibles antes de iniciar la inferencia.
    \item La configuración define correctamente el flujo requerido por el modelo.
    \item El directorio de resultados permite conservar la respuesta consolidada.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item El procesamiento deberá respetar la concurrencia autorizada por el servicio.
    \item Los PDF deberán procesarse página por página para controlar el uso de recursos.
    \item Los archivos temporales deberán permanecer aislados y eliminarse después de la operación.
    \item La configuración deberá ser compatible con el motor y el modelo seleccionados.
    \item La inferencia deberá mantenerse dentro de los límites de memoria, contexto, tamaño y tiempo establecidos.
\end{elementosmodulo}

\item[Estructura general] El módulo recibe el documento y la configuración activa, prepara cada página, ejecuta la inferencia mediante el adaptador correspondiente y consolida las respuestas parciales en un resultado único.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Ruta local de una imagen o documento PDF.
    \item Identificación del motor y modelo activos.
    \item Prompt, perfil y parámetros de inferencia.
    \item Identificador de correlación y ruta de resultados.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación del tipo, tamaño e integridad del archivo.
    \item Normalización de imágenes o renderización de páginas PDF.
    \item Ejecución de la inferencia sobre cada página.
    \item Validación y ordenamiento de las respuestas parciales.
    \item Consolidación del contenido y los metadatos.
    \item Cálculo de tiempos y estado de finalización.
    \item Eliminación de los recursos temporales.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Transcripción consolidada del documento.
    \item Contenido y metadatos individuales por página.
    \item Motor y modelo utilizados.
    \item Tiempos y motivo de finalización.
    \item Errores de lectura, preparación o inferencia.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Persistencia y Trazabilidad de Resultados (M8)}
\label{subsec:modulo_m8}

\begin{definicionmodulo}

\item[Propósito] El módulo Persistencia y Trazabilidad de Resultados tiene como propósito conservar el estado de las tareas y los productos generados por los VLM Server, relacionándolos de manera inequívoca con el documento de origen. Además, mantiene los antecedentes necesarios para reconstruir cada ejecución y recuperar los resultados ante interrupciones del sistema.

\item[Alcance] El módulo registra tareas, elementos, asignaciones, intentos, transiciones de estado, transcripciones, metadatos y errores. Mantiene una copia persistente en el Sistema Coordinador y, cuando corresponde, utiliza el Servicio de Conexión con MySQL para registrar el resultado en la base institucional. También conserva la relación entre el procesamiento inicial y sus reintentos o reprocesamientos.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Gestión y Orquestación Distribuida de Tareas, que proporciona estados y asignaciones.
    \item Resultados generados por el VLM Server.
    \item Módulo Servicio de Conexión con MySQL, utilizado para almacenar los resultados institucionales.
    \item Almacenamiento local persistente para el historial y la recuperación de tareas.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item Cada resultado puede asociarse con una tarea, un elemento y un documento de origen.
    \item Los identificadores de tareas, elementos e intentos son únicos.
    \item El almacenamiento local permanece disponible para el Sistema Coordinador.
    \item Las escrituras institucionales pueden realizarse de forma transaccional.
    \item Los resultados conservados permiten reanudar una carga pendiente sin repetir la inferencia.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item El documento original no deberá eliminarse ni sobrescribirse.
    \item Un resultado incompleto o inválido no deberá registrarse como exitoso.
    \item Toda transición deberá conservar su fecha, origen e identificador de correlación.
    \item Los reintentos y reprocesamientos deberán mantener la relación con sus ejecuciones anteriores.
    \item Una falla al escribir en MySQL no deberá eliminar la copia persistente del resultado.
    \item Las escrituras repetidas deberán evitar duplicados y mantener un estado consistente.
\end{elementosmodulo}

\item[Estructura general] El módulo recibe estados o resultados, valida su integridad, los conserva localmente y ejecuta las escrituras institucionales autorizadas. Si una escritura externa falla, mantiene el resultado pendiente para permitir su recuperación posterior.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Identificadores de tarea, elemento, intento y documento de origen.
    \item Estado, servidor asignado y marcas temporales.
    \item Transcripción y metadatos generados por el VLM Server.
    \item Modelo, motor, tiempos y antecedentes de error.
    \item Estado de la operación de escritura en MySQL.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación estructural del estado o resultado recibido.
    \item Asociación con la tarea y el documento de origen.
    \item Registro persistente de la transición o producto.
    \item Envío de los datos autorizados al Servicio de Conexión con MySQL.
    \item Confirmación de la persistencia o registro de la carga pendiente.
    \item Actualización del estado individual y general de la tarea.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Estado persistido de tareas y elementos.
    \item Transcripción y metadatos almacenados.
    \item Relación trazable entre origen, tarea, servidor, modelo y resultado.
    \item Confirmación o estado pendiente de la escritura institucional.
    \item Información histórica disponible para consulta y recuperación.
    \item Registro de los errores de persistencia.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Postprocesamiento (M9)}
\label{subsec:modulo_m9}

\begin{definicionmodulo}

\item[Propósito] El módulo Postprocesamiento tiene como propósito transformar las transcripciones generadas por los VLM Server en contenido normalizado y adecuado para su indexación. Corrige diferencias de representación, recupera la estructura por páginas y elimina elementos técnicos que no deben formar parte de las búsquedas.

\item[Alcance] El módulo interpreta el formato estructurado de cada resultado, extrae el contenido útil, conserva el orden de las páginas, normaliza codificación, espacios y saltos de línea, y genera una representación canónica. También identifica resultados vacíos, dañados o incompletos para impedir que sean incorporados al índice como documentos válidos. No modifica la transcripción original ni responde consultas de búsqueda.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Administrador de Índice, que proporciona la transcripción y recibe el contenido normalizado.
    \item Transcripciones y metadatos recuperados desde MySQL por el proceso de sincronización.
    \item Reglas de normalización y validación definidas para los formatos de salida vigentes.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item Cada resultado contiene un identificador del documento y una estructura reconocible.
    \item El orden de las páginas puede determinarse a partir de los metadatos almacenados.
    \item La transcripción original permanece disponible para fines de trazabilidad.
    \item Las reglas de normalización son deterministas y versionables.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item El postprocesamiento no deberá alterar el significado del contenido reconocido.
    \item La transcripción original deberá conservarse sin modificaciones.
    \item La misma entrada y versión de reglas deberán producir la misma salida.
    \item Los resultados inválidos deberán registrarse con su causa y excluirse del índice.
    \item La separación y numeración de páginas deberá mantenerse durante la normalización.
\end{elementosmodulo}

\item[Estructura general] El módulo obtiene un resultado persistido, valida su estructura, extrae el texto por página, aplica las reglas de normalización y entrega una representación canónica al Administrador de Índice.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Identificador y metadatos del documento procesado.
    \item Transcripción estructurada y contenido por página.
    \item Formato y versión del resultado generado.
    \item Reglas y versión del proceso de normalización.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación y análisis de la estructura recibida.
    \item Extracción y ordenamiento del contenido por página.
    \item Normalización de codificación, espacios y saltos de línea.
    \item Eliminación de envoltorios y artefactos técnicos.
    \item Verificación del contenido resultante.
    \item Registro de la versión y del estado del postprocesamiento.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Texto normalizado del documento.
    \item Contenido normalizado e identificación de cada página.
    \item Metadatos requeridos para la indexación.
    \item Versión de las reglas aplicadas.
    \item Estado válido, vacío o rechazado con su causa.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Administrador de Índice (M10)}
\label{subsec:modulo_m10}

\begin{definicionmodulo}

\item[Propósito] El módulo Administrador de Índice tiene como propósito mantener en MySQL una representación consultable del contenido documental normalizado. Sincroniza los nuevos resultados y sus modificaciones con el índice de texto, conservando la relación entre cada entrada, la página correspondiente y el documento institucional de origen.

\item[Alcance] El módulo utiliza el seguimiento de cambios y el último procesamiento exitoso para detectar resultados nuevos o modificados, solicita su postprocesamiento y crea o actualiza las entradas del índice almacenado en MySQL. Mantiene puntos de control para reanudar la sincronización, evita duplicados y permite reconstruir el índice a partir de las transcripciones persistidas. No ejecuta inferencia ni define la presentación de los resultados al usuario.

\item[Dependencias]
\begin{elementosmodulo}
    \item Módulo Postprocesamiento, que proporciona contenido canónico por documento y página.
    \item Servidor MySQL institucional, utilizado para detectar cambios, recuperar transcripciones y almacenar el índice textual.
    \item Almacenamiento de puntos de control y estados de sincronización.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item Cada documento y página poseen identificadores estables.
    \item Los resultados exitosos pueden distinguirse de versiones fallidas o incompletas.
    \item El origen dispone de una señal o criterio para identificar cambios pendientes.
    \item La estructura del índice permite operaciones de alta, actualización y eliminación por identificador.
    \item El contenido persistido permite reconstruir completamente el índice.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item Solo deberán indexarse resultados válidos y asociados a documentos identificables.
    \item La sincronización deberá ser idempotente y no crear entradas duplicadas.
    \item El punto de control solo deberá avanzar después de confirmar las operaciones del lote.
    \item Una falla parcial deberá permitir reanudar la actualización sin perder cambios.
    \item Cada entrada deberá conservar la referencia al documento y página de origen.
    \item La reconstrucción del índice no deberá modificar las transcripciones persistidas.
\end{elementosmodulo}

\item[Estructura general] El módulo identifica los cambios posteriores al último procesamiento exitoso, obtiene y normaliza las transcripciones correspondientes, actualiza el índice de MySQL en lotes y registra un nuevo punto de control únicamente cuando las operaciones finalizan correctamente.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Punto de control y último procesamiento exitoso.
    \item Identificadores de resultados nuevos, modificados o eliminados.
    \item Texto y metadatos normalizados por documento y página.
    \item Configuración del índice de texto y tamaño de los lotes.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Detección de cambios pendientes desde el último procesamiento exitoso.
    \item Recuperación y validación de los resultados vigentes.
    \item Solicitud de postprocesamiento cuando sea necesario.
    \item Creación, actualización o eliminación de entradas del índice.
    \item Confirmación del lote y registro del nuevo punto de control.
    \item Registro de errores y conservación de los cambios pendientes.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Índice de texto de MySQL actualizado.
    \item Entradas relacionadas con sus documentos y páginas de origen.
    \item Punto de control de la última sincronización exitosa.
    \item Cantidad de elementos creados, actualizados, omitidos o fallidos.
    \item Información de diagnóstico y estado de la sincronización.
\end{elementosmodulo}

\end{definicionmodulo}

\subsection{Definición del Módulo: Buscador Avanzado de Documentos (M11)}
\label{subsec:modulo_m11}

\begin{definicionmodulo}

\item[Propósito] El módulo Buscador Avanzado de Documentos tiene como propósito permitir que los usuarios localicen documentos a partir de su contenido transcrito y de sus metadatos. Proporciona resultados relevantes y trazables que conducen al documento y a la página donde se encontró cada coincidencia.

\item[Alcance] El módulo recibe consultas textuales y filtros, construye la expresión de búsqueda, consulta el índice y ordena las coincidencias según su relevancia. Admite términos, frases, coincidencias exactas y aproximadas, además de perfiles con distintos niveles de precisión. Presenta fragmentos de contexto, metadatos, página y acceso al documento asociado. No modifica el índice ni los documentos de origen.

\item[Dependencias]
\begin{elementosmodulo}
    \item Índice textual alojado en MySQL y mantenido por el módulo Administrador de Índice.
    \item Metadatos institucionales autorizados para complementar las coincidencias.
    \item Sistema documental desde el cual se visualizan los documentos originales.
    \item Mecanismo de autenticación y autorización de la aplicación consumidora.
\end{elementosmodulo}

\item[Supuestos]
\begin{elementosmodulo}
    \item El índice se encuentra disponible y contiene referencias vigentes.
    \item Cada resultado puede relacionarse con un documento accesible para el usuario autorizado.
    \item Los filtros recibidos corresponden a campos consultables.
    \item El sistema consumidor puede abrir el documento o página referenciada.
\end{elementosmodulo}

\item[Restricciones]
\begin{elementosmodulo}
    \item Las consultas deberán respetar los permisos del usuario sobre los documentos.
    \item Los valores ingresados deberán validarse antes de construir la consulta al índice.
    \item La cantidad de resultados por respuesta deberá estar limitada y paginada.
    \item Los fragmentos presentados deberán codificarse de forma segura.
    \item La ausencia o desactualización del índice deberá informarse sin entregar resultados engañosos.
    \item El módulo no deberá alterar el documento, la transcripción ni las entradas del índice.
\end{elementosmodulo}

\item[Estructura general] El módulo valida la consulta y sus filtros, solicita coincidencias al índice, complementa los resultados con metadatos autorizados y devuelve una respuesta paginada con enlaces al documento y a la página correspondiente.

\textbf{Entradas:}
\begin{elementosmodulo}
    \item Texto o términos de búsqueda.
    \item Filtros documentales e institucionales.
    \item Perfil de búsqueda y nivel de tolerancia solicitado.
    \item Parámetros de ordenamiento y paginación.
    \item Identidad y permisos del usuario solicitante.
\end{elementosmodulo}

\textbf{Ejecución:}
\begin{elementosmodulo}
    \item Validación y normalización de la consulta.
    \item Aplicación de filtros y restricciones de acceso.
    \item Selección de coincidencia exacta, textual o aproximada según el perfil.
    \item Ejecución de la consulta sobre el índice textual.
    \item Cálculo u obtención de la relevancia de las coincidencias.
    \item Recuperación de metadatos y fragmentos de contexto.
    \item Ordenamiento y paginación de la respuesta.
\end{elementosmodulo}

\textbf{Salidas:}
\begin{elementosmodulo}
    \item Lista paginada de documentos y páginas coincidentes.
    \item Puntaje u orden de relevancia.
    \item Fragmentos de texto con el contexto de la coincidencia.
    \item Metadatos autorizados del documento.
    \item Referencia para abrir el documento y la página encontrada.
    \item Mensajes de validación o diagnóstico cuando la consulta no pueda ejecutarse.
\end{elementosmodulo}

\end{definicionmodulo}
