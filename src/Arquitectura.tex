\section{Arquitectura del Sistema}

\subsection{Diagrama de Contexto}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\linewidth]{images/Contexto.png}
    \caption{Diagrama de contexto del sistema propuesto.}
    \label{fig:diagrama_contexto_sistema}
\end{figure}

Como se observa en el diagrama de contexto de la Figura~\ref{fig:diagrama_contexto_sistema}, la solución se organiza en torno a cuatro componentes principales: el \textbf{Sistema Coordinador}, los \textbf{Servidores VLM}, el \textbf{Sincronizador} y \textbf{DocuDigital}. Estos componentes utilizan la base de datos institucional alojada en el servidor MySQL de la Subsecretaría para consultar, registrar y actualizar la información documental.

El \textbf{Sistema Coordinador} centraliza la administración del procesamiento documental. Su \emph{back end} incorpora los mecanismos de control de acceso y permisos, registro de operaciones, procesamiento de documentos y administración de tareas, mientras que su \emph{front end} permite a los administradores supervisar y gestionar las ejecuciones. El coordinador obtiene y modifica la información necesaria en la base de datos institucional y distribuye las solicitudes de procesamiento hacia los Servidores VLM mediante sus respectivas API.

La comunicación entre el Sistema Coordinador y los Servidores VLM sigue una relación de uno a muchos, lo que permite que una instancia del coordinador gestione múltiples servidores de procesamiento en paralelo. Cada \textbf{Servidor VLM} expone una API y dispone de un servicio Linux compuesto por un daemon VLM y uno o más procesos \texttt{llama-server}. La comunicación interna se realiza mediante un \emph{Unix domain socket}, utilizado también por la interfaz de línea de comandos para administrar y diagnosticar el servicio de manera local. Esta arquitectura permite distribuir la carga, incorporar nuevos servidores y sustituir modelos o configuraciones sin modificar la lógica central de gestión.

Una vez obtenidas las transcripciones, el \textbf{Sincronizador} consulta los resultados almacenados en la base de datos institucional, aplica las operaciones de postprocesamiento requeridas y actualiza el índice utilizado para la recuperación de información. De esta forma, el buscador avanzado integrado en \textbf{DocuDigital} puede consultar el contenido procesado y presentar al usuario los documentos y páginas relacionados con su búsqueda.

Los usuarios finales interactúan exclusivamente con el portal web de DocuDigital, mientras que los administradores acceden a las funciones de supervisión del Sistema Coordinador y, cuando es necesario, a las herramientas de operación de los Servidores VLM. Esta separación de responsabilidades desacopla la consulta documental, la coordinación de tareas, el procesamiento mediante modelos de visión y lenguaje y la indexación de resultados, facilitando la escalabilidad, la continuidad operacional y la adaptación del sistema a los recursos computacionales disponibles.

\subsection{Diagrama de Arquitectura}

La arquitectura de la solución se compone de un \textbf{Sistema Coordinador}, uno o más \textbf{Servidores VLM}, un servidor institucional \textbf{MySQL}, una base de datos local \textbf{SQLite} y los componentes asociados al postprocesamiento, la indexación y la búsqueda documental, como se observa en la Figura~\ref{fig:arquitectura}. El Sistema Coordinador concentra la preparación de los documentos, la administración de las tareas y la persistencia de los resultados. Los Servidores VLM funcionan como nodos independientes de procesamiento y permiten ejecutar documentos en paralelo.


Dentro del Sistema Coordinador, el módulo \textbf{M1: Portal Web y Control de Acceso} proporciona la interfaz utilizada para autenticar a los usuarios, crear solicitudes de procesamiento y consultar el estado de las tareas. Las solicitudes son enviadas al módulo \textbf{M3: Preparación de Lotes Documentales}, que organiza los documentos seleccionados y valida la información requerida mediante el módulo \textbf{M2: Servicio de Conexión con MySQL}.


Una vez validada la solicitud, el módulo M3 crea una nueva tarea y la entrega al módulo \textbf{M4: Gestión y Orquestación Distribuida de Tareas}. Este componente divide los lotes en unidades de procesamiento, administra sus estados y distribuye los documentos entre los Servidores VLM disponibles. De esta forma, una misma ejecución puede aprovechar varias instancias de procesamiento sin depender de un único servidor.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.85\linewidth]{images/Arquitectura.png}
    \caption{Diagrama de arquitectura del sistema propuesto.}
    \label{fig:arquitectura}
\end{figure}


Cada Servidor VLM expone el módulo \textbf{M5: API de Integración con VLM Server}, que recibe las solicitudes del Sistema Coordinador y devuelve las respuestas generadas. El módulo \textbf{M6: Administración del Servicio VLM} controla la operación interna del servidor, incluyendo la comunicación con el servicio Linux y la administración del modelo activo. Finalmente, el módulo \textbf{M7: Procesamiento e Inferencia Documental} ejecuta el modelo configurado y genera la transcripción del documento, junto con sus tiempos, estados y posibles errores.


Los resultados son enviados nuevamente al módulo M4, que actualiza el progreso de la tarea y los entrega al módulo \textbf{M8: Persistencia y Trazabilidad de Resultados}. Este componente conserva la relación entre cada resultado y su documento de origen, registra los antecedentes operativos en SQLite y utiliza el módulo M2 para almacenar las transcripciones consolidadas en MySQL.


SQLite mantiene el historial de procesamiento, los estados de las tareas y la información necesaria para realizar seguimiento o recuperar ejecuciones interrumpidas. MySQL actúa como fuente institucional de los documentos, almacena los resultados procesados y mantiene la información utilizada posteriormente por los mecanismos de indexación y búsqueda.


Después de la persistencia, el módulo \textbf{M9: Postprocesamiento} aplica las operaciones de limpieza y normalización necesarias sobre las transcripciones. El contenido resultante es utilizado por el módulo \textbf{M10: Administrador de Índice}, encargado de incorporar y actualizar la información dentro del índice textual. La actualización considera los cambios registrados en la base de datos y el último procesamiento exitoso, evitando reconstrucciones completas cuando no son necesarias.


Finalmente, el módulo \textbf{M11: Buscador Avanzado de Documentos} consulta el índice textual y permite recuperar documentos a partir del contenido transcrito y de sus datos asociados. Los resultados mantienen la referencia al documento original y a la página correspondiente, permitiendo integrar la búsqueda con DocuDigital.
